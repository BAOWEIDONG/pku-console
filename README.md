# 北大医疗 · 超级管理后台 v9.1（去私域版）

线上：https://baoweidong.github.io/pku-console/

一个后台管所有端：服务、商品、价格、订单、客户、健康管理、五好生活、内容、权限。

本版本在 V9.1 基础上恢复完整功能，仅移除企业微信私域运营、获客线索池、短信/站内信自动触达、触达旅程与消息模板等私域营销内容；客户档案、预约履约、健康管理、权益、订单与五好生活保留。

## 菜单架构：7 个工作区 + 页内业务域 + 同屏视图

左侧只保留 7 个工作区，每个工作区只有一个入口；进入后不再用弹窗或聚合页二次分流：

- 工作区：指挥 / 客户 / 商品 / 健管 / 项目 / 内容 / 平台，直接点选，名称常显；
- 工作区内用一行业务页签组织，例如客户 = 客户 360 / 交易与订单 / 预约与履约 / 结算 / 上下游；
- 业务页签内的视图切换并入标题行，不形成第三级菜单；页面、筛选、列表、详情与操作默认同屏完成；
- 客户总览、全渠道客户、客户 360 合并为一个客户入口，不再拆三个页面；
- 商品 = 服务目录 / 实物商品 / 价格与履约 / 端上服务；健管 = 健康工作台 / 服务履约 / 计划与随访 / 结果与报告；
- 项目 = 五好生活 / 内容与转化 / 会员与任务 / 减重营 / 规则与报告；内容 = 品牌站 / 职工端 / 内容与素材 / 渠道与入口；
- 平台 = 公共资源 / 权限与设置 / 发布与日志；旧的重复路由只做兼容别名，不再生成独立工作区。

融合后的关键交互：

- 五好会员不是名单弹窗：左侧会员名单、右侧会员全貌，五维、任务、风险、授权、报告与下一步动作同屏；
- 健康档案、客户 360、服务 360 都按对象聚合，详情里可以直接编辑、建计划、排随访、发权益与查看全部痕迹；
- 表格默认整行可点：订单、学员、结算、号源、任务、指标、机构、科室、师资、内容等列表直接点行进入编辑或详情，不必再找最右箭头；
- 商品与轮播都有图片入口：商品首图、图集、图文详情块与 SKU 可配置；轮播可上传/换图并配置跳转、投放时间与排序；
- 上下游是独立对象：甲方业务公司拥有员工客户与合同，乙方服务商提供医疗服务和实物商品，服务、商品、履约与应付结算都能追回主体；
- 所有配置写入同一套业务数据，发布后由后台统一驱动现有及后续新增的 H5，不做“三端各自维护”。

本版本仍不包含企业微信私域、获客线索池、自动触达旅程与消息模板；电话回访、服务预约、订单、权益与健康管理保留。

- **会员运营**：五维分数、任务完成、连续打卡、风险、授权与下一步；

## 为什么改（v4）

v3 是「按 H5 分菜单」——品牌站、职工端、减重营各一套。结果：

- 服务被拆成三份，价格、规则、素材跟着端走，同一个体检三个地方维护；
- 每加一个 H5 就要加一个后台入口，运营要重新学；
- 菜单按端堆叠，越加越长。

v4 改成**按业务对象组织**，端只作为「渠道」存在：

```
服务与商品   服务商品 / 价格与政策 / 服务包 / 服务机构 / 预约设置
客户与交易   订单中心 / 履约 / 领奖 / 兑换 / 结算对账 / 客户 / 企业权益
内容与渠道   渠道与触点 / 内容中心 / 品牌站页面 / 职工端页面 / 品牌与主题
项目运营     五好生活 / 减重营（营期·规则·报告）
平台         工作台 / 发布 / 日志 / 角色权限 / 设置
```

新增一个 H5 或小程序，只是「渠道与触点」里加一条记录，勾选可见服务即可上线，后台菜单不变。

## 服务商品化（v4 核心）

一个服务 = SPU + N 个 SKU + 规则 + 素材 + 渠道：

- **价格**：成本价、结算价、建议售价、协议价、税点、有效期、次数；自动算毛利率，低于 20% 标红阻断发布。
- **规则**：最早/最远可约、免费取消、爽约、退款、有效期、服务须知。
- **素材**：主视觉、详情长图、流程图、视频、FAQ。
- **渠道**：勾选投放端，服务即出现在对应端的列表与搜索。
- **服务包**：把单品打包成套餐（五好生活、体检+检后、五高一重、企业家尊享）。

## 五好生活怎么做

产品定义：**年度会员制 + 五维打分 + 月度可执行任务**。

| 维度 | 核心指标 | 权重 | 权益 |
|---|---|---|---|
| 吃好 | 膳食结构达标天数 | 25% | 营养评估 1 次 + 月度方案 12 次 |
| 睡好 | 睡眠 ≥7h 天数 | 20% | 睡眠评估 2 次 + 改善计划 |
| 动好 | 每周运动 ≥150 分钟 | 25% | 体测 4 次 + 运动处方 12 周 |
| 心好 | 压力自评达标月数 | 15% | EAP 6 次 + 压力评估 |
| 查好 | 完成体检与复测 | 15% | 年度体检 + 报告解读 2 次 |

三档定价：基础 ¥3,980 / 进阶 ¥6,980 / 尊享 ¥12,800（结算价 2,880 / 5,200 / 9,800）。

落地四步：① 做成服务包上架 → ② 入组五维评估打基线 → ③ 每周每维 1 个任务、月度出指数 → ④ 年度报告与续费。

系统里对应：`服务包` 配置售卖、`五好生活` 看板看指数与达标率、`五好配置` 管维度权重/任务库/评分规则。

## 配置如何真正联动（v5）

链路：后台编辑 → 本地工作区 → 发布闸门 → `config.json` → 三端 H5 的 `pku-bridge.js` 读取 → 应用并重渲染。

- 三个 H5 都通过 `assets/pku-bridge.js` 读取 `pku-console/config.json`（GitHub Pages 已返回 `access-control-allow-origin: *`）。
- `config.json` 包含：品牌 / 联系方式、渠道页面上下线、职工端模块与服务上下架、减重营奖励档位、五好生活配置。
- 职工端：模块可显隐、服务可上下架、热线与标题可替换；品牌站：联系方式替换与页面入口上下线；减重营：榜单开关与主题变量。
- 浏览器 localStorage 中没有 GitHub Token 时，发布只作用于本地工作区；「连接 GitHub / 推送配置」保存 Token 后，发布会自动推送并让三端在 1 分钟内生效。

## v3 的三个变化

**1. 从「三套后台」变成「一套超级后台」**
导航不再按应用切断，而是按业务域连续排列，顶部是「全局 · 跨端」：品牌与主体、跨端内容、服务机构、主题与入口——这些配置三端共用一份，改一处三端同时生效。每条配置都标注影响面（哪个端、哪个页面）。

**2. 角色权限可配置**
7 个内置角色（超级管理员 / 运营负责人 / 营养师 / 教练 / 品牌运营 / 企业 HR / 审计只读）× 18 个模块 × 查看·编辑·发布三级权限。切换角色后菜单按权限收窄、页面进入只读态、编辑与发布被真正拦截，不是摆设。

**3. 预览就是真实 H5**
右侧设备默认加载**线上真实页面**（iframe），所见即用户所见；改动配置时自动切到「配置模拟」，用同一份数据渲染改动后的效果。两种模式随时切换。

## 关键机制

- **单一数据源**：`data.js` 种子 → `store.js` 状态（localStorage）→ 所有页面、预览、发布读同一份。
- **变更队列**：每次编辑进「待发布」，发布中心按端分组展示差异，写说明、导出 JSON、或推送到仓库，保留历史与回滚点。
- **权限门禁**：`Store.can(group, level)` 同时驱动导航、只读态、按钮可用性与发布按钮。
- **预览双模**：`live` 走 iframe 线上真实页；`mock` 走 `preview.js` 同源渲染。

## v3.2 修复（交互有效性）

- **列表开关失效**：表格行是副本，`indexOf` 恒为 -1，导致上下架 / 启停写到了 `list[-1]`。改为按 id 兜底索引，全站 223 个开关全部验证可写回。
- **旧缓存兼容**：升级后自动补齐 `shared / rbac / settings` 等新结构，角色 ID 失效时回落到超级管理员，不会因为浏览器里的旧数据让按钮集体失灵。
- **只读可一键恢复**：以受限角色浏览时，页面顶部提示条提供「切换为超级管理员」，避免误以为功能坏了。
- **新建按钮全部可用**：指标、徽章、商品、服务、模块、字段、问答、Banner、资讯、科室、成员、机构、公告、问卷题目等由「提示」改为真实表单抽屉并写入数据。
- **线上实况**：品牌站改用移动端页面 `mobile.html`；加载超时自动降级到配置模拟并提示。
