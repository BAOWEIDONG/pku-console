# 北大医疗 · 健康服务超级后台 v10

线上：https://baoweidong.github.io/pku-console/

这不是“三个 H5 的协同后台”，而是一套可扩展的健康服务操作系统：**后台维护共享数据与业务能力，多个前端应用只负责各自的展示与交互**。当前接入三个真实 H5，后续新增 H5 通过“应用矩阵”注册、绑定共享能力、配置页面落点后即可复用同一套后台。

当前接入：

| 端 | 仓库 | 后台落点 |
| --- | --- | --- |
| 健康训练营 | `versionall` | 16 个页面：营期学员、首页、打卡规则、记录批注、30 项指标、徽章、积分、连续奖励、商城、履约、活动、团队、报告、账号、食谱工程 |
| 品牌站 | `PKU-introduce` | 6 个页面：品牌首页、师资团队、分院网络、学科科室、健康营项目、关于北大医疗 |
| 职工健康 | `pku-employee-health` | 首页、28 项服务目录、服务模块宫格、服务详情、预约规则、预约记录、权益、健康档案、科普讲座、机构、五好生活、健康问答、消息 |

此外提供跨产品能力：客户中心与客户 360、健康管理与随访、干预项目与结果评估、五好会员运营、价格与组合、订单中心、结算对账、共享素材库、电话跟进、H5 页面对照、能力边界、发布中心、角色与日志。

## 系统架构

### 1. 应用矩阵

- **应用注册**：名称、代码、域名、类型、状态、页面规模、角色、负责人、版本与发布时间。
- **共享能力绑定**：客户与会员、服务与商品、健康管理、五好生活、权益与订单、内容与素材、档案与报告、发布与权限。
- **独立发布**：每个应用有自己的页面落点与发布状态，新增应用不需要复制一套后台。
- **能力矩阵**：一眼看到每个应用复用了哪些后台能力、复用率多少、哪些能力尚未接入。
- **扩展流程**：注册应用 → 绑定共享能力 → 配置页面落点 → 发布与验收。

### 2. 导航结构

侧栏按“业务中台 / 前端应用 / 平台”三层组织：

- **业务中台**：客户中心、服务与商品、健康管理、五好生活、内容与素材、订单与结算。这些能力由所有应用共享。
- **前端应用**：健康训练营（versionall）、品牌站（PKU-introduce）、职工健康（pku-employee-health）。这里只配置各前端自己的页面、导航与展示字段。
- **平台**：发布中心、H5 页面对照、能力边界、角色与日志。

## v10 的关键变化

- **按真实 H5 重建**：数据由三个 H5 的源码、页面与 mock 数据抽取生成，不再使用自造的渠道 / 商品 / 泛健康域。
- **多应用架构**：新增应用矩阵、共享能力绑定与能力矩阵；首页按应用动态生成入口，接入新 H5 不再需要改一套后台。
- **导航始终可读**：深蓝固定侧栏，分组文字常显；按端展开当前分组，不再依赖悬浮提示。
- **应用主色区分**：健康训练营 `#f07a43`、品牌站 `#2c8aa8`、职工健康 `#ff6a13`，新应用可单独设置主题色。
- **整卡可点**：服务、专家、机构、预约、客户等列表整行 / 整卡进入详情，不再只能点最右箭头。
- **图片成为一等公民**：商品主图、多图图集、图文详情、轮播 / 活动横幅、服务主图、专家头像、机构图片都支持上传与替换。
- **客户 360**：个人信息、训练营打卡、批注、积分奖励、职工预约、权益、报告、授权、消息、备注、电话待办与全部时间线聚合在一页。
- **变更影响不跳页**：从任意页面打开抽屉，看完即可关闭回到原页面。
- **预约闭环**：服务介绍 → 代客下单 → 待确认 → 已确认 → 服务中 → 已完成 / 已取消；取消按规则退回权益次数。
- **服务与商品可新增**：服务目录、积分商城和「服务与商品规划」都能新增；新增服务或商品会自动生成一条运营计划，商品继续进入主图 / 图集 / 图文详情配置。
- **食谱工程**：全天食谱 18 套、餐次模板 28 个、菜品 114 道、食材 50 种、营养补剂 18 件；支持封面、四餐组合、营养重算、过敏原与整卡编辑。
- **食谱搭配器与推荐规则**：按均衡 / 控糖 / 减脂 / 低嘌呤目标套用四餐组合，生成新的全天食谱；推荐规则明确人群、触发条件与边界，不替代营养门诊。
- **健康管理闭环**：健康管理总览、风险与计划、随访工作台、服务履约台、项目队列、结果评估与企业健康报告；风险规则、计划里程碑、随访结果和履约异常都能落到责任人与下一步。
- **五好生活全链路**：主题与权益、企业档位、履约核销、会员档案、打卡审核、月度报告、授权隐私，以及吃好 / 睡好 / 动好 / 心好 / 查好六个主题工作台。
- **服务模块与宫格**：职工端首页五宫格可配置名称、短名、排序、图标、配色与启停；模块关闭只隐藏入口，不删除服务与历史预约。
- **交易与结算**：服务预约、积分兑换、打卡奖励统一进入订单中心；合作方账期、授信与对账单可查、可编辑，但不接支付、开票和打款接口。
- **运营规划**：服务上线计划、商品补货计划、体检套餐与名额、每周排期模板、日期例外，统一放在「运营规划」分组。
- **不伪装接口**：没有企业微信、短信、物流、支付、排班或设备同步接口。主动触达只做电话人工待办，不做私域获客与营销自动化。

## 真实生效边界

现有 H5 均已接入 `assets/pku-bridge.js`，刷新后读取 `config.json`。新增应用也走同一套 bridge 与发布流程。当前真实生效 6 类：

1. 客服电话 / 热线 / 地址文本替换
2. 职工端站点标题
3. 职工端 5 大模块显隐
4. 职工端服务上下架
5. 品牌站导航入口显隐
6. versionall 排行榜入口显隐

以下内容后台可编辑、可保存、可导出，但静态 H5 不会自动读取：轮播图、商品图集与图文、服务名称与介绍、专家与机构图片、文章正文、五好任务、预约排班、消息正文、食谱与营养补剂。**运营规划中的套餐、名额、排期模板与日期例外只保存后台计划台账，不会写入 `config.json`，也不会自动覆盖医院号源；食谱工程同样只保存后台，当前 H5 只有饮食打卡，没有食谱详情与采纳入口。** 健康计划、随访、项目队列、结果评估、五好会员审核与企业报告只保存后台台账；不接医院号源、设备同步、支付、开票或财务打款。

**明确不做**：企业微信私域运营、获客、营销自动化、短信 / 自动外呼、触达旅程与私域活跃运营。需要联系职工时，只生成电话人工待办并记录结果。

## 本地运行

```bash
cd work
python3 -m http.server 8766
# 打开 http://localhost:8766/work/pku-console/
```

数据保存在浏览器 `localStorage`，键为 `pku-console-v10`。换浏览器或清缓存会回到真实 H5 初始数据。

## 发布

1. 在「发布中心」下载或复制 `config.json`；
2. 提交到 `pku-console` 仓库并等待 GitHub Pages 构建；
3. 逐个应用刷新检查联系方式与入口显隐；
4. 回到「H5 页面对照」核对生效状态。

仓库不保存 GitHub Token，部署只在本机使用环境变量。
